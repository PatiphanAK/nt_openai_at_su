# SkillSchool (full-stack)

A Skillshare-style app for schools: university students share **course
content summaries**, each checkable against the course's **required topics**,
with a **recommendation system that matches summaries by writing style**
(format, depth, tone, examples/formulas/diagrams).

Fully self-contained full stack: Next.js App Router + **Prisma** + Supabase
Postgres. The old Go/Fiber backend is gone — the Next.js app owns auth
(same JWT model + API contract) and all data access.

## Stack

| Layer | What |
| --- | --- |
| UI | Next.js 16 App Router, React 19, Tailwind CSS v4 |
| Data | Prisma ORM → Supabase Postgres (`prisma/schema.prisma`) |
| Auth | bcryptjs hashes + jose HS256 JWT (72h, `sub` claim) in an httpOnly cookie — compatible with tokens the old Go API issued |
| Mutations | Server Actions (`lib/actions.ts`) with `revalidatePath` |

## Run locally

```bash
bun install
cp .env.example .env      # fill in DATABASE_URL / DIRECT_URL / JWT_SECRET
bun run db:push           # sync Prisma schema to the database
bun run db:seed           # demo students, courses, summaries, organic likes
bun run dev               # http://localhost:3000
```

Demo login: `pat@skillschool.demo` / `password123` (every seeded student uses
that password; emails are `<handle>@skillschool.demo`).

## Routes

| Route | Purpose |
| --- | --- |
| `/` | Hero, "Matched to your summary style" rail (signed in), trending, courses |
| `/browse` | All summaries with search / course / style filters |
| `/summary/[slug]` | Style-aware rendering (bullets, outline, narrative, Q&A, mind map, flashcards), required-topic coverage checklist, like/save, same-style recs |
| `/share` | Publish a summary (requires login) |
| `/courses`, `/courses/[code]` | Required topics + per-topic summary coverage |
| `/students/[handle]` | Profiles, style fingerprints, similar students |
| `/login`, `/register` | Cookie-session auth |

## JSON API (parity with the old Go API)

| Endpoint | Behavior |
| --- | --- |
| `POST /api/register` | `{email, name, password}` → 201 `{user, token}` (+ session cookie); 409 if taken |
| `POST /api/login` | `{email, password}` → 200 `{user, token}`; 401 on bad credentials |
| `GET /api/me` | Bearer token or session cookie → `{user}`; 401/404 |

## Where things live

- `prisma/schema.prisma` — `users` (adopts the table the Go backend created),
  `courses`, `summaries`, `likes`, `saves`
- `lib/prisma.ts` — client singleton; `lib/data.ts` — queries mapped to app types
- `lib/auth.ts` — hashing, JWT, cookie session; `lib/actions.ts` — server actions
- `lib/recommend.ts` — style vectors + cosine similarity; taste profile =
  uploads (×2) + likes (×1), with human-readable match reasons
- `prisma/seed.ts` — demo content (idempotent; never touches real users)

## Deploy on Vercel

1. Push this repo to GitHub, then import it in Vercel.
2. Set **Root Directory** to `frontend/front` (Vercel auto-detects Next.js; bun
   lockfile is respected).
3. Add environment variables: `DATABASE_URL`, `DIRECT_URL`, `JWT_SECRET`
   (same values as local). Prisma Client is generated by the `postinstall`
   script; `binaryTargets` are not needed since Prisma 6 resolves engines on
   the Vercel build image.
4. Sync the schema once before first deploy (locally: `bun run db:push`) —
   no migration step runs at build time. For team workflows later, switch to
   `prisma migrate dev` + `prisma migrate deploy`.
5. Deploy. For best latency, set the project's function region to
   `ap-southeast-1` (near the Supabase instance).

## Content conventions for summary bodies

Plain text lines, interpreted by `components/SummaryBody.tsx`:

- `- ` bullet — indent two spaces per tree level (bullets / outline / mind map)
- `Q: ` / `A: ` question–answer pair (Q&A sheets and flashcards)
- `> ` tip / callout box
